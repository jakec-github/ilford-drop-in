Override card — condensed

Three directions. All drop the Matches/Sets panels: the description is the "which shifts", and the changes are the "what's different". Only what an Override actually changes is shown — no more "as the pattern generates it" rows. Clicks are wired lightly so you can feel the editing states.

A · Headline and changes

The description is the card's title. Changes sit under it as chips; click one to edit it in place, "+ Change" adds one. Number, drag, remove stay on one header line.

  • The Natural/Raw switch goes: natural is the default, "Write the rule yourself" is the way to raw (already the NaturalField's escape hatch), and raw gets a "Describe it instead" link back.
  • Tools dim until hover/focus so a list of overrides reads as a list of rules, not of buttons. (Always full strength on touch.)
  • Closest to today's code: same article, same NaturalField, same ShapeSeats — the props grid becomes a chip row.

B · Ledger with one open

Each Override is a single summary row; one opens at a time into its editor. Best when there are many — the define preview's "Override 3" is easy to find. Click a row.

  • In the open editor, unset properties stay as "+ Replace the shape" / "+ Pin" rather than vanishing, since there's room.

  • Editing needs popovers off each chip (shape counts, the pin adder), since there's no room inline — more to build, and popovers on a phone are fiddly.
  • Save status would move to the section header ("All saved") rather than per card.

Recommendation

A. It gets most of B's and C's compactness (a typical override drops from ~9 rows of UI to 2), keeps editing in place as today, and reuses every existing piece. B is worth revisiting if Organisers end up with a dozen overrides; C's arrow could be borrowed into A later if the description and chips ever feel disconnected.
